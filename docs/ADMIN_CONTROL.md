# مركز إدارة Chess Studio

من «المزيد ← إدارة المنصة» بعد تسجيل الدخول بحساب مدير. الواجهة تدعم العربية والإنكليزية والهاتف والتابلت. لا يُنشأ حساب مدير أو كلمة مرور افتراضية.

## الأقسام

| القسم | ما يمكن إدارته |
|---|---|
| نظرة عامة | الحسابات والمباريات والاشتراكات المؤقتة وطابور التحليل والإيراد المؤكد لبوابات الموقع فقط |
| المستخدمون | البحث، التفعيل والتعطيل، دور المستخدم/المدير، إبطال الجلسات، إسناد خطة لمدة محددة وإيقاف الوصول المدفوع |
| الخطط | السعر بالدينار والمدة والوصف باللغتين والمميزات وحدود المعلّم والتدريب وخطط المتابعة |
| الخصومات | نسبة أو مبلغ، مدة الصلاحية، خطة مستهدفة، حد إجمالي وحد لكل مستخدم |
| مزودو AI | Groq Cloud وxAI Grok وOpenRouter وOpenAI، النموذج والمفتاح والأولوية والبدائل وإيقاف AI |
| الدفع | ZainCash وFIB وGoogle Play، تشغيل/إيقاف، بيئة اختبار/إنتاج، بيانات الاعتماد واختبار OAuth |
| الإعلانات | بانر للرئيسية/المعرفة/اللعب أو نافذة إعلان، صورة ونص ورابط باللغتين، توقيت واستهداف وأحداث وحدود تكرار |
| الطلبات | حالة الدفع الفعلية وإعادة الاستعلام من المزود وسجل Google Play، دون زر وهمي لتأكيد التحصيل |
| الموقع والتوليد | الاسم والوصف والتواصل والصيانة وإيقاف AI وتوليد التمارين والهدف اليومي 21–48 |
| المحرك والعمال | إعدادات Stockfish وسرعة التحليل وموارده والسقف العام لطلبات المعلّم وإعادة المهام الفاشلة |
| سجل التغييرات | من نفّذ الإجراء ووقته وموضوعه، دون المفاتيح أو كلمات المرور أو purchaseToken |

الخطة المجانية تبدأ بالمميزات الحالية لتبقى الحسابات القديمة عاملة. لا تُنشأ خطط مدفوعة أو أسعار تجريبية تلقائياً. تعطيل خطة يمنع شراءها الجديد؛ المشتركون الحاليون يحتفظون بها حتى انتهاء المدة. تعديل المميزات ينطبق عليهم فوراً. السقوف الفعلية هي الأصغر بين حد الخطة وسقف المنصة: المعلّم حتى 100، الشرح الموسع حتى 40، خطط المتابعة حتى 3 يومياً. حساب المدير يتجاوز بوابات المميزات، وليس قيود حماية المحرك.

إيقاف الوصول المدفوع يضع حجزاً إدارياً يمنع إعادة تفعيله تلقائياً من Google أو طلب دفع معلّق. لإزالته أسند للمستخدم خطة من اللوحة، بما فيها المجانية. هذا الإجراء **لا يلغي التجديد في Google Play ولا يعيد الأموال**؛ التجديد والاسترداد يُداران لدى المتجر أو شركة الدفع. إسناد خطة إلى خطة مطابقة يضيف أيامها إلى المدة المتبقية، والتحويل لخطة مختلفة يبدأ المدة الجديدة فوراً.

## التشغيل والترقية

اتبع README للتثبيت الكامل. لإدارة موقع قائم خذ نسخة SQLite صحيحة ونسخة محمية من وحدة `studiodata` والمفاتيح قبل الترقية؛ لا تستبدل قاعدة البيانات بقاعدة نموذجية. `core.setup()` يضيف جداول `control_*` وفهارسها، ويضيف `shown_at` عند غيابه؛ إعادة تشغيله لا تحذف البيانات.

```bash
# ضمن تثبيت المشروع الكامل بعد مراجعته وبناء صورته
docker compose build studio
docker compose up -d --no-deps studio control-sync
docker compose exec -T studio python -m studio.admin --help
```

استخدم أمر promote الموثق في README للبريد الموجود إن لم يكن لديك مدير. لا تمنح الإدارة لحسابات غير موثوقة: المدير يملك إعدادات الخدمات والحسابات والتحصيل. بوابات الدفع تبدأ متوقفة، والصيانة متوقفة.

`control-sync` عامل صغير يتحقق من ثلاثة طلبات معلقة وثلاثة اشتراكات Google كحد أقصى في الدورة. لا ينشئ دفعات. يحتفظ كل طلب بنسخة إعداداته وقت الإنشاء، حتى يستمر التحقق بعد تدوير المفاتيح. لا تحذف ملفات الاعتماد القديمة ما دامت هناك طلبات أو اشتراكات مرتبطة بها. على الخادم القديم الذي يستخدم systemd بدلاً من Compose، شغّل `python -m studio.control_worker` كل دقيقة بصورة الإصدار الجديدة مع نفس وحدة البيانات. حدّث صورة مهمة التمارين اليومية أيضاً حتى تُطبق أزرار الإيقاف والهدف الجديد؛ لا تشغّل مولّدين يوميين معاً.

## حفظ مفاتيح الخدمات

أدخل المفتاح الجديد ثم كلمة مرور حساب المدير لتأكيد الحفظ. الحقل الفارغ يبقي المفتاح الموجود. تغيير بيئة بوابة الدفع يتطلب بيانات اعتماد البيئة الجديدة. ردود API تعرض مؤشرات «محفوظ» فقط؛ لا ترسل قيمة المفتاح أو مسار ملفه للمتصفح. اختبار المصادقة يؤكد OAuth فقط، ولا يثبت جاهزية المنتج أو صحة كل مراحل التحصيل.

المفاتيح مخزنة في **ملفات خاصة بصلاحيات 0600 داخل مجلد 0700** في `/studio-data/control-private`، ويمكن تغيير المجلد بمتغير `CONTROL_PRIVATE_DIR`. هذه حماية صلاحيات ملفات، وليست تشفيراً مستقلاً: مدير الخادم ومالك النسخ الاحتياطية يستطيعان قراءتها. لا تنقل هذا المجلد أو ملفات المزود أو قواعد المستخدمين إلى GitHub. انسخ المجلد وقاعدة البيانات وملف إعداد مزودي المعلّم معاً عند النسخ الاحتياطي؛ يتضمن المجلد مفتاح ربط حساب Google ولا يجوز تغييره عشوائياً بعد ربط مشتريات.

## ZainCash وFIB

1. أنشئ حساب تاجر واحصل على بيانات بيئة الاختبار من الشركة.
2. أنشئ خطة مدفوعة فعلية ومميزاتها من اللوحة.
3. اضبط `STUDIO_BASE_URL` إلى عنوان HTTPS العام الصحيح وملفات ارتباط آمنة وفق README. لن ينشئ النظام checkout بعنوان محلي أو HTTP.
4. أدخل Client ID وClient Secret؛ أضف API Key لـZainCash. عنوان الإنتاج يؤخذ من الشركة أثناء تفعيل التاجر، ولا يُفترض تلقائياً. يسمح النظام بنطاقات HTTPS الرسمية فقط.
5. فعّل sandbox واختبر المصادقة ثم مسار الدفع كاملاً بحسابات الاختبار. تظهر النتيجة `test_paid` ولا تمنح عضوية مدفوعة حقيقية.
6. بعد موافقة الشركة والتحقق من تكامل حسابك، أدخل بيانات الإنتاج واختر live وفعّل البوابة.

ZainCash v2: سجّل لدى الشركة عنوان `https://YOUR-DOMAIN/api/billing/zaincash/webhook`؛ وثائق الشركة تقول إن webhook خاص بالإنتاج ولا يعمل في UAT. تُفحص قيمة `webhook_token` بتوقيع HS256 بمفتاح ملف الطلب، ثم يُعاد الاستعلام عن المعاملة؛ لا تُعتمد حالة الدفع من المتصفح أو جسم الإشعار وحده. FIB يأخذ عنوان callback عشوائياً خاصاً بكل طلب. العامل الخلفي وزر التحقق يعيدان الاستعلام أيضاً. يجب أن يطابق المبلغ والعملة ومعرّف المعاملة الطلب المحفوظ، وعند ZainCash يطابق orderId كذلك.

الخصم والسعر يحسبهما الخادم، والحجز المتزامن يمنع تجاوز سقف الخصم. الطلب المعلق يحجز استخدام الخصم حتى يثبت فشله/استرداده لدى المزود، حتى لو مرّ وقت انتهاء واجهة الدفع؛ هذا يمنع الدفع المتأخر من تجاوز الحد. لا تُكرر إنشاء طلب تلقائياً بعد انقطاع الشبكة؛ احتفظ بالمعرّف وافحص حالة المعاملة لدى التاجر. لا يتضمن الإصدار زر تنفيذ استرداد مالي، ويعرض استرداد ZainCash الذي يؤكده الاستعلام ويوقف العضوية المرتبطة به فقط.

**التحقق الحالي:** اختبارات آلية باستجابات مزود مصطنعة، دون حساب تاجر أو دفعات حقيقية. يجب اختبار عقد API الفعلي لحسابك في sandbox قبل الإنتاج؛ لا تعني علامة «محفوظ» أن الشركة قبلت البيانات.

## Google Play — اشتراكات Android

هذه واجهات خادم وإعدادات متجر، وليست تطبيق Android جاهزاً ولا زر Google Play وهمياً على الويب.

1. أنشئ تطبيق Android في Play Console، ثم منتجات اشتراك وخطط أسعار وعروض. أسعار المتجر وخصوماته تُدار في Play Console، وخصومات الموقع تخص بواباته فقط.
2. فعّل Android Publisher API وامنح حساب الخدمة أقل صلاحيات قراءة الاشتراكات والتحقق والإقرار اللازمة لتطبيقك. ارفع JSON من لوحة المدير؛ لا تضمّنه داخل التطبيق.
3. أدخل package name واربط product ID بمعرّف خطة مدفوعة موجودة في الموقع. فعّل السماح بمشتريات الاختبار أثناء الاختبار فقط.
4. من التطبيق، بعد تسجيل الدخول بنفس حساب الموقع: `GET /api/billing/google-play/account`. مرّر `obfuscated_account_id` إلى `BillingFlowParams.Builder.setObfuscatedAccountId(...)` قبل فتح Billing Library.
5. بعد الشراء أرسل `POST /api/billing/google-play/verify` بجسم `{"purchase_token":"...","product_id":"..."}` مع جلسة المستخدم و`X-CSRF-Token` وفق مصادقة المشروع. لا تخزن كلمات مرور المستخدم داخل التطبيق ولا تمنح المميزات من `purchaseToken` وحده.
6. الخادم يستعلم `purchases.subscriptionsv2.get` ويتحقق من المنتج وربط الحساب والانتهاء والحالة، ثم يقر الشراء المعلّق عند الحاجة. ACTIVE وGRACE وCANCELED قبل الانتهاء يمكن أن تمنح الوصول؛ HOLD/PAUSED/EXPIRED لا تمنحه. مشتريات الاختبار وبيئة sandbox لا تمنح عضوية إنتاجية.
7. اضبط Real-time developer notifications عبر Pub/Sub إلى `https://YOUR-DOMAIN/api/billing/google-play/notifications` مع **Authenticated push / OIDC**، ثم أدخل Audience والبريد الموثق نفسه في اللوحة. تُفحص هوية Google وتوقيع RS256 والجمهور والبريد والحزمة، ثم يعاد الاستعلام؛ لا تمنح RTDN عضوية من نص الإشعار.
8. فعّل `control-sync` لاستدراك تغيّر الاشتراكات المسجلة عند تأخر الإشعارات. رموز الشراء فريدة ومربوطة بمستخدم واحد، وقيمها داخل الملفات الخاصة فقط.

حالة اختبار Play تستخدم `testPurchase` من Google حتى لو أُرسلت عبر إعداد live، فلا تُحتسب كتحصيل حقيقي. لا تُحسب إيرادات Google من أسعار خطط الموقع؛ راجع تقرير Play Console. الربط يتطلب اختباراً بتطبيق Android وحسابات license testers قبل إتاحته للجمهور.

## البنرات ونافذة الإعلان

ارفع PNG/JPEG/WebP حتى 2MB، ثم اكتب العنوان والوصف وزر الرابط باللغتين. لا يُسمح بـHTML أو SVG أو روابط javascript. اختر موضع البانر أو «نافذة»، ثم الحدث: زيارة الرئيسية/المعرفة/اللعب، تسجيل الدخول، إكمال درس، حل لغز، انتهاء مباراة تدريبية أو فتح مراجعة. أحداث الإنجاز تُثبت من بيانات المستخدم المحفوظة ولا تعتمد على ادعاء المتصفح.

يمكن تحديد «بعد كم حدث»، وتاريخ البداية والنهاية، والخطة المستهدفة، والأولوية والحد اليومي وفترة الانتظار. يُحسب اليوم بتوقيت بغداد. تُحجز مرات التسليم لمنع طلبين متزامنين من تجاوز الحد، والظهور الفعلي يسجل عندما توافق الواجهة على العرض. المعاينة لا تزيد الأرقام. نافذة الإعلان تنتظر العودة للرئيسية وإغلاق نوافذ الدراسة حتى لا تقطع الدرس؛ تغلق بزر ×. خطة `no_ads` تمنع العرض. الإعلانات تخص واجهة المستخدم المسجل؛ شاشة تسجيل الدخول ليست موضع إعلان في هذا الإصدار.

## التحقق والمراجع

```bash
PYTHONPATH=.:tests python -m unittest test_control_center test_google_play -q
npm ci
npm test
```

الاختبارات تغطي CSRF وصلاحيات المدير وكلمة تأكيده وحماية آخر مدير، حجب المفاتيح حتى من أخطاء validation، إصدارات الخطط وانتهائها، أسعار الخادم والخصومات، عدم تكرار منح المدة، وضع الاختبار، اختلاف المبلغ والمرجع، Google وربط الحساب وإعادة الاستخدام والإقرار والإشعارات الموقعة والإيقاف الإداري، وأحداث الإعلان وحدوده وملكيته وتعطيله وروابطه. لا تجري الاختبارات تحصيلاً خارجياً.

مصادر API الرسمية، تمت مراجعتها في 2026-11-23:

- [ZainCash v2](https://docs.zaincash.iq/)
- [FIB Web Payments](https://fib.iq/integrations/web-payments/)
- [Google Play billing security](https://developer.android.com/google/play/billing/security)
- [Google subscriptionsv2.get](https://developers.google.com/android-publisher/api-ref/rest/v3/purchases.subscriptionsv2/get)
- [Google subscription lifecycle](https://developer.android.com/google/play/billing/lifecycle/subscriptions)
