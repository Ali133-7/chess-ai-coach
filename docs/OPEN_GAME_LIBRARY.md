# مكتبة المباريات المحلية المفتوحة

الغرض: دراسة مباريات حقيقية كاملة **كما سُجّلت في PGN**، بأسماء الطرفين والسنة، والبحث وإعادة العرض والتشغيل التلقائي بالعربية والإنكليزية. قد تنتهي المباراة بالاستسلام أو اتفاق التعادل؛ لا نضيف نقلات متخيّلة حتى المات.

## المصدر وحدود التغطية

- المصدر المعتمد: [أرشيف Lichess الرسمي للبث](https://database.lichess.org/#broadcasts)، و[قائمة الملفات](https://database.lichess.org/broadcast/list.txt) و[بصماتها](https://database.lichess.org/broadcast/sha256sums.txt). عند الفحص في 2026-11-25 تضم القائمة 82 ملفاً شهرياً من 2020-01 إلى 2026-10. العدد المنشور في المصدر يشمل جميع الفئات والسجلات، وليس عدد المباريات المقبولة محلياً.
- قسم **Broadcasts** مرخّص **CC BY-SA 4.0** تحديداً. لا نطبّق عليه عنوان CC0 العام الموجود أعلى صفحة Lichess. تُحفظ نسبة العمل للمصدر، ورابط المباراة والبطولة، وبصمة الأرشيف وترتيب السجل. تبقى البيانات المعدّلة تحت الترخيص نفسه.
- هذه المكتبة ليست أرشيف Chessgames.com، وليست كل مباراة شطرنج في العالم. لم تُنسخ تعليقات أعضائه أو تتجاوز حدود وصوله. مصادر غير واضحة الترخيص لا تُضاف تلقائياً.
- الوضع الافتراضي `--scope gm` يتطلب **WhiteTitle=GM وBlackTitle=GM** صراحة. لا يُستنتج اللقب من الاسم أو Elo. `--scope all` يبني مكتبة أوسع لكل الألقاب من المصدر نفسه؛ استخدم ملف قاعدة منفصلاً لكل نطاق.
- الأعداد الدقيقة، الأشهر، الاستبعادات وأسبابها موجودة في `game-library-manifest.json` المرفق مع النسخة. الشهر الذي انتهى استيراده لا يعني قبول كل سجلاته.

## التخزين والتحقق

`master-library.sqlite3` ملف عام منفصل عن `studio.sqlite3` و`knowledge.sqlite3`. الموقع يقرأه فقط؛ لا يستورد البيانات من الشبكة عند فتح الصفحة ولا يشغّل الاستيراد عند بدء الخادم. مساره الافتراضي بجانب قاعدة المنصة، ويمكن تغييره بـ`CHESS_LIBRARY_DB`.

يحتوي الفهرس على بيانات المباراة وPGN مضغوط وتقييمات رقمية مضغوطة وفهرس FTS5. تُولّد SAN/FEN والقوائم القانونية والشروح عند فتح مباراة واحدة. بذلك لا تُخزّن ملايين نسخ الشروح ومصفوفات النقلات القانونية. البحث في الفهرس الموسع يجمع **بدايات الكلمات** بـAND؛ مثل `Pragg Giri`. يظل البحث النصي القديم متاحاً للعينة الصغيرة. تُدمج نتائج العينة والفهرس دون تكرار معرف المباراة.

الاستيراد يتحقق من SHA-256 المنشور، والقطع والوضعية الابتدائية، وكل نقلة في الخط الرئيسي، وعلامة النتيجة في جسم PGN ومطابقتها للرأس، وعدم استمرار اللعب بعد نهاية قانونية، والتاريخ. يُستخدم UTCDate عندما يغيب تاريخ موثوق. السجلات بلا سنة، وChess960، والمباريات غير المكتملة أو بلا نقلات، والسجلات غير القانونية تُستبعد مع إحصاءات. لا تُخمن السنة من اسم الملف.

منع التكرار يعتمد SHA-256 لقائمة: الاسمان بعد توحيد الحالة، التاريخ، الحدث، الجولة، FEN البداية وكل نقلات UCI بالترتيب. هذا يمنع تكرار الهوية المتطابقة؛ اختلاف أسماء اللاعبين أو بيانات الحدث في المصدر قد يبقي نسختين لنفس اللقاء. لا ندّعي حل مطابقة كل صيغ الأسماء.

يحفظ كل commit دفعة المباريات ومصدرها ومؤشر الاستئناف **في معاملة واحدة**. إعادة الأمر تستأنف الملفات، وتقرأ حتى مؤشر آخر دفعة مكتملة، ولا تعيد إدخال المباريات. تغيير SHA أو النطاق يُرفض لحماية الاستئناف. يُحذف الملف الشهري المضغوط بعد اكتمال معاملته، إلا مع `--keep-archives`. يُحفظ manifest المصدر. حد الملف المضغوط 128 MiB، واللعبة 600 ply، والحمولة المفكوكة 2 MiB؛ يقف البناء قبل استهلاك آخر 1 GiB افتراضياً. الافتراضي عامل واحد، ويمكن استخدام `--workers 2` إلى `--workers 4` لمعالجة أرشيفات منفصلة بالتوازي. اضبط حدود CPU/RAM للحاوية ولا تستهلك موارد الموقع. لا يستدعي البناء خدمة AI مدفوعة.

## معنى الشرح والتحليل

- كل نقلة لها شرح محلي ثنائي اللغة عن **حقائق الرقعة**، مثل التطوير والأخذ والكش والمربعات المهددة. هذا وصف تعليمي آلي، وليس تعليق أستاذ بشري أو حكماً بأن النقلة الأفضل.
- تقييمات PGN الرقمية محفوظة مع `source=broadcast-eval`. إعدادات المحرك الأصلي غير معروفة. تظهر التغطية الفعلية، وتبقى التقييمات المفقودة فارغة. لا نستنتج خسارة سنتيبيدق أو تصنيف خطأ من فرق تقييمين مجهولي الإعدادات.
- زر **حلّل هذه الوضعية بـ Stockfish** يفتح فاحص الوضعية الموجود في المشروع ويطلب تحليلاً محلياً عند الحاجة، ضمن ميزانية المحرك وحد المستخدم. التحليل لا يبدل نقلات المباراة المسجلة. توفره يتطلب Stockfish. تحليل FEN وحده لا يعيد تاريخ التكرار السابق.
- التشغيل التلقائي والتنقل بعد تحميل المباراة يعملان محلياً، دون طلب API لكل نقلة. لم يُحسب تحليل عميق مستقل لكل وضعية في الأرشيف؛ ذلك يحتاج ميزانية تشغيل منفصلة.

## بناء مكتبة بنفسك

من جذر المستودع، داخل virtualenv:

```bash
python -m pip install -r requirements-data.txt
python scripts/build_game_library.py --database ./game-library/master-library.sqlite3 --work-directory ./game-library/archives --scope gm
```

لاختبار شهر واحد أضف `--months 1`. لاستيراد كل فئات المصدر استخدم `--scope all` مع **قاعدة جديدة ومجلد عمل منفصل**. دون `--months` تُعالج كل الملفات الموجودة في قائمة المصدر لحظة بدء البناء. لا يعني ذلك كل أرشيفات الشطرنج على الويب. تعتمد المدة والمساحة على النطاق والجهاز؛ لا تشغله داخل عامل الويب.

يمكن البناء على سيرفر دون تثبيت Python إضافي:

```bash
docker build -f deploy/Dockerfile.game-library -t chess-game-library:local .
mkdir -p game-library
docker run --rm --cpus 1 --memory 768m --pids-limit 64 --security-opt no-new-privileges --user "$(id -u):$(id -g)" --mount type=bind,src="$PWD/game-library",dst=/data chess-game-library:local
```

أعد الأمر نفسه بعد انقطاعه. لإضافة أشهر نُشرت لاحقاً أضف `--refresh-index` صراحة؛ الاستئناف العادي يستخدم قائمة المصدر المحفوظة. لا تربط volume حسابات الموقع بهذه الحاوية. لمراقبة التقدم تُطبع إحصاءات JSON كل 200 سجل. يمكن التحقق والتغليف من بيئة أدوات البيانات:

```bash
python scripts/game_library_artifact.py verify --database ./game-library/master-library.sqlite3 --deep
python scripts/game_library_artifact.py package --database ./game-library/master-library.sqlite3 --output ./library-release
```

التغليف ينشئ snapshot متسقاً بواسطة SQLite Backup API، ويفحص سلامة SQLite والجداول والأعداد، ثم ينتج gzip وmanifest ببصمتين وأعداد فعلية ومصادر وتراخيص. لا يقبل جداول الحسابات أو المفاتيح. استخدم مجلد إخراج جديداً لكل إصدار. النقلات تُفحص كاملة أثناء الاستيراد؛ لإعادة فحصها كاملة أثناء التغليف أضف `--deep`. يذكر manifest هل أُعيد الفحص، وقد يستغرق ذلك وقتاً طويلاً للأرشيفات الكبيرة.

## تثبيت النسخة داخل المشروع

احصل على `master-library.sqlite3.gz` و`game-library-manifest.json` من **الإصدار نفسه**؛ راجع manifest من قناة تثق بها. بصمة ملف من نفس قناة تنزيل مخترقة ليست توقيع هوية مستقلّاً.

للتشغيل المحلي خارج Docker:

```bash
python scripts/game_library_artifact.py install --archive ./library-release/master-library.sqlite3.gz --manifest ./library-release/game-library-manifest.json --destination ./studio-data/master-library.sqlite3
```

حدد `CHESS_LIBRARY_DB` إذا كان `STUDIO_DB` في مسار مختلف. مع Compose والـvolume الافتراضي، من جذر المشروع:

```bash
docker compose run --rm --no-deps -v "$PWD/library-release:/public:ro" studio python scripts/game_library_artifact.py install --archive /public/master-library.sqlite3.gz --manifest /public/game-library-manifest.json --destination /studio-data/master-library.sqlite3
```

المثبت يفحص الحجم والبصمتين وSQLite والجداول والأعداد، ويجهز الملف المؤقت على نفس القرص ثم يعيد تسميته ذرياً. لا يسمح بوجهة اسمها `studio.sqlite3` أو `knowledge.sqlite3`. إذا وُجدت مكتبة سابقة يتوقف؛ `--replace` يحتفظ بنسخة احتياطية منها. أوقف أي builder يكتب إلى الوجهة أولاً؛ وجود WAL/SHM يرفض الاستبدال. ملفات الحسابات والمفاتيح لا تُقرأ ولا تُغيّر. لا تحتاج إعادة استيراد العينة القديمة أو حذفها.

من الواجهة: **مركز المعرفة ← مباريات الأساتذة**، ثم بحث/سنة/نتيجة/نوع المباريات. اختيار «كل مباريات الأرشيف» لا يضيف سجلات غير موجودة في الملف المثبت. API المحمي:

- `GET /api/knowledge/masters?q=Carlsen&scope=gm&year=2024&limit=12&offset=0`
- `GET /api/knowledge/masters/library-status` للأعداد ومصادر الاستيراد وحالته.
- `GET /api/knowledge/masters/{id}` لكل النقلات والشروح والتغطية.
- `GET /api/knowledge/masters/{id}/pgn` لتصدير مباراة مع المصدر والترخيص.

ترخيص كود المشروع GPL-3.0-or-later في `LICENSE`، وتراخيص البيانات منفصلة في `THIRD_PARTY_NOTICES.md` وملفات manifest. إضافة الترخيص لا تغيّر رؤية مستودع GitHub تلقائياً.
