# إدارة البنرات والإعلانات

من حساب المدير افتح **المزيد ← إدارة المنصة ← البنرات والإعلانات**. تعرض الخريطة مواضع أعلى المحتوى وأسفله واليسار واليمين. اضغط الموضع لإنشاء حملة، أو استخدم «إضافة حملة». لا ينشئ التحديث حملات تجريبية أو حساب Google افتراضياً.

## صورة ورابط أو نص

1. اختر «صورة ونص ورابط»، وأدخل اسم الحملة بالعربية والإنجليزية. يمكن رفع PNG أو JPEG أو WebP حتى 2MB و6 ميغابكسل، وبحد 4096px لكل ضلع، وإضافة نص بديل ووصف وزر ورابط HTTPS أو مسار داخلي.
2. اختر إظهار الصورة كاملة أو ملء الإطار مع قص الأطراف. يفضل بوستر أفقي للأعلى والأسفل، وعمودي للجوانب؛ عرض العمود الجانبي 160px.
3. حدد الصفحات والخطة المستهدفة، وبداية الحملة ونهايتها بتوقيت جهازك، والأولوية، وعدد الزيارات السابقة، والحد اليومي لكل لاعب والفاصل بالدقائق.
4. فعّل الحملة واسمح بإظهارها، ثم احفظ. «إيقاف» يستبعد الحملة، و«إخفاء» يحجبها مع الاحتفاظ بحالة تفعيلها. يمكن إدارة الحالتين بصورة مستقلة، وإيقاف النظام كله أو أي موضع من إعدادات النظام.
5. «معاينة» تعرض التصميم، و«معاينة على الصفحة» تعرض مواضع الحملات المفعّلة الظاهرة ضمن وقتها وصفحاتها. المعاينة الإدارية لا تسجل مشاهدات أو نقرات ولا تحمل Google؛ لا تحاكي عضوية لاعب محدد أو حدود تكراره. اخرج من شريط المعاينة للعودة للإدارة.

المدير لا يتلقى الإعلانات العادية. تظهر للاعبين المسجلين داخل صفحات المنصة المختارة؛ صفحات الدخول والإدارة والدفع والإعدادات خارج المواضع الجديدة. خطط `no_ads` تمنع الإعلانات. المواضع القديمة ونافذة الإعلان تبقى متوافقة؛ Google متاح للمواضع الأربعة الجديدة فقط.

## قواعد العرض والقياس

- لا تظهر الجوانب ولا يرسل الخادم مرشحاتها تحت عرض **1800px**. يمكن رفع الحد إلى 1920 أو 2200. CSS يمنعها أيضاً تحت 1800 حتى لو تلاعب العميل بعرضه المرسل. يشير الحد إلى عرض نافذة المتصفح بوحدات CSS؛ التكبير يؤثر فيه.
- الجوانب أعمدة منفصلة عن المحتوى، وليست طبقات فوق الرقعة. الأعلى والأسفل داخل تدفق الصفحة، دون شريط ثابت. تختفي المواضع أثناء نوافذ الدراسة والمراجعة واللعب التدريبي النشط وعند الطباعة.
- حتى أربع حملات من المواضع الجديدة في الزيارة، واحدة لكل موضع، مع إعداد لتقليل العدد. الاختيار بالأولوية ثم الأقل عرضاً مؤخراً للاعب ثم معرّف ثابت؛ لا توجد ادعاءات بتنبؤ AI بالعائد.
- لا تسجل قراءة قائمة المرشحات مشاهدة. يلزم ظهور نصف البنر لمدة ثانية، وتحميل الصورة أو تأكيد امتلاء وحدة Google، ثم إقرار الخادم. يمنع الخادم التكرار للزيارة والحملة، وينفذ الحدود اليومية والفاصل بصورة ذرية حتى مع طلبين متزامنين. اليوم محسوب بتوقيت بغداد.
- زر الإغلاق للبوسترات المخصصة فقط؛ لا يضاف زر إغلاق أو رابط مخصص لوحدة Google. إغلاق اللاعب يحفظ الإخفاء في حسابه من ساعة إلى أسبوع، 24 ساعة افتراضياً. فشل حفظ الشبكة يخفيه في الجلسة الحالية فقط.
- تفحص الواجهة تغييرات الإعدادات كل 15 ثانية عندما تكون الصفحة نشطة؛ انتهاء الجدولة يخفي البنر بتوقيت محلي أيضاً. إعلان معروض يبقى ثابتاً خلال الزيارة. لا يوجد تحديث دوري لوحدات Google.
- الإحصاءات المحلية ليست منصة محاسبة إعلانية أو كشف احتيال: يمكن لعميل معدل إرسال إشارات ظهور زائفة. نقرات البوستر المخصص تسجل مرة لكل مشاهدة مقرّة؛ لا تعترض المنصة نقرات Google ولا تخمّن إيراداته.
- عند فشل صورة، أو تعذر تحميل سكربت Google، أو تأكيد `data-ad-status=unfilled`، يجرب الموضع بوستراً مخصصاً آخر من المرشحات المتاحة ضمن الحدود؛ إن لم توجد يبقى فارغاً.

## Google AdSense

استخدم **وحدات Display يدوية**، دون لصق سكربتات أو HTML في اللوحة. معرّفا الناشر والوحدة عامان، وليسا مفتاح API سرياً.

1. جهّز حساب AdSense وموقعاً مؤهلاً لدى Google على نطاق HTTPS حقيقي. اضبط `STUDIO_BASE_URL` وHost والبروكسي وملفات الارتباط على النطاق نفسه وفق دليل التشغيل. النفق المحلي HTTP وعناوين IP لا تشغّل Google في هذا التكامل.
2. جهّز متطلبات الخصوصية والموافقة، بما فيها منصة CMP معتمدة حيث يطلبها Google. خيار «منصة الموافقة جاهزة» إقرار من المدير؛ **لا يثبت CMP ولا يجمع الموافقات ولا يتحقق من إعداد حسابك**. لا تفعّله قبل تجهيز ذلك فعلياً.
3. في «إعدادات النظام وGoogle» أدخل `ca-pub-` متبوعاً بـ16 رقماً، وأكد جاهزية الموافقة ثم فعّل Google. يتطلب تغيير هذه الإعدادات كلمة مرور المدير الحالية.
4. أنشئ حملة بمصدر Google واختر الموضع وأدخل معرّف الوحدة الرقمي من AdSense، دون صورة أو رابط مخصص. فعّلها ضمن التوقيت والاستهداف. افحص `/ads.txt` على نطاقك؛ يصدر سطر Google للناشر المحفوظ فعلياً حتى لو كانت وحدات Google متوقفة، لتمكين إثبات الملكية قبل تشغيلها. لا تجمع وحدات Auto ads خارج هذا النظام دون مراجعة توزيعها كي لا تتكرر المواضع.
5. أعد تحميل الصفحة بعد تفعيل Google أو تغيير الناشر. عند الدخول من صفحة بلا nonce، تهيئ الواجهة صفحة الرئيسية مرة واحدة تلقائياً إن كان Google مؤهلاً؛ لا تعيد تحميل درس أو نموذج قيد الكتابة، ويوجد حارس يمنع حلقة التحديث. تتطلب سياسة CSP في الاستجابة nonce جديداً؛ لا تخفض الحماية يدوياً لتجاوز غياب هذا الرمز. اختبر بحساب مستخدم، وراجع التشخيص والأرباح داخل AdSense. لا تنقر إعلاناتك للتحقق.

في الوضع الافتراضي تبقى CSP محلية صارمة. عند جاهزية Google، يضيف الخادم nonce متغيراً ومربوطاً بالجلسة والنطاق لاستجابة صفحة مستخدم مؤهل، مع `strict-dynamic` وتطبيق قالب Google الرسمي لـscript-src وobject-src وbase-uri، مع منع تضمين المنصة نفسها عبر frame-ancestors. لا تضاف قيود default-src أو قوائم نطاقات لأن موارد خدمة الإعلانات قد تتغير؛ بقية أنواع موارد الإعلان تتبع إعدادات المتصفح وسياسة Google. يطبق وضع Google قالب التوافق الموثق، بما فيه `unsafe-eval` و`unsafe-inline` مع nonce و`strict-dynamic`؛ المتصفحات الحديثة تتجاهل السماح العام بالسكربت المضمّن مع nonce. هذه صلاحيات أوسع لسكربت الطرف الثالث وموارده، وليست عزلًا له؛ تبقى السياسة الافتراضية محلية صارمة، ولا يسمح بلصق HTML أو JavaScript من المدير. تختبر حالات HTTPS حجب سكربت مزروع في HTML دون nonce. عند إنهاء جلسة حمّلت Google أو الانتقال لحساب مدير يعاد تحميل المستند للتخلص من السكربت السابق.

يحمّل التكامل سكربت Google الرسمي عند ظهور الموضع فقط، مباشرة في الصفحة دون iframe مخصص حوله. يصدر طلباً واحداً فقط لكل موضع في المستند، حتى عند اختلاف الحملات أو التنقل أو تغيير المقاس. العودة من الخلفية لا تستبدل الوحدة. مهلة تحميل السكربت 12 ثانية؛ بعد طلب الإعلان لا تحذف مهلة الامتلاء الوحدة المعلقة، وتظل تنتظر الحالة الفعلية لتجنب إلغاء إعلان بطيء أو إنشاء طلبات بديلة متكررة. لا يسجل `unfill-optimized` كإعلان ممتلئ. عند إزالة الوحدة بسبب تغيير سياق الدراسة أو العرض، لا يعاد طلب Google لهذا الموضع حتى تحميل مستند جديد. معاينة المدير لا تتصل بخوادم الإعلانات.

جرى اختبار البوابات والتحقق والأوضاع المحلية دون ناشر حقيقي أو طلبات إعلانية. اعتماد الموقع وCMP والتسليم الفعلي وتوافق سياسات حسابك تحتاج تحققاً على النطاق المؤهل؛ التفعيل في اللوحة لا يضمن القبول أو الأرباح.

مصادر Google الرسمية التي بُني عليها التكامل:

- [CSP المدعومة وnonce](https://support.google.com/adsense/answer/16283098?hl=en).
- [سياسة عدم وضع الكود داخل iframe مخصص](https://support.google.com/adsense/answer/3394713?hl=en).
- [متطلبات CMP المعتمدة](https://support.google.com/adsense/answer/13554116?hl=en).
- [إعداد ads.txt](https://support.google.com/adsense/answer/12171612?hl=en).

## الترقية والفحص

الترحيل إضافي داخل `control_store.setup`: يحفظ معرّفات الحملات والتسليم السابق، ويضيف إعدادات العرض وجدول تفضيلات الإخفاء وفهرس منع تكرار الزيارة. تسلسل الترحيل محمي بقفل كتابة أثناء بدء أكثر من خدمة. مخطط `database/studio.schema.sql` محدث دون بيانات مستخدمين أو حملات. لا تستبدل قاعدة الإنتاج باللقطة العامة.

خذ نسخة احتياطية متسقة، وافحص الترقية على نسخة معزولة، ثم حدّث الموقع والعامل والمزامنة والمؤقتات إلى المصدر نفسه وفق دليل النشر والتراجع. تحديث المتصفح بـCtrl+F5 يحمّل ملفات الإعلانات الجديدة معاً.

```bash
PYTHONPATH=.:tests python -m unittest test_advertising -q
npm test
npx playwright test tests/browser/advertising.spec.cjs
npm run test:ads-security
python scripts/advertising_load_test.py --output advertising-load-smoke.json
```

تغطي الاختبارات الصلاحيات وCSRF وتعارض النسخ والتوقيت والعضويات والقفل والتكرار والتوازي والترحيل دون فقدان الصفوف، وتوقيت الظهور والإغلاق واللغتين وعزل الجلسات. حالات المتصفح تختبر أربعة أحجام شاشة وتتحقق أيضاً من عدم تداخل الأعمدة عند 1920px، وإخفائها مع فتح المراجعة، وإنشاء حملة ومعاينتها دون احتساب، وعدم تحميل Google محلياً. جميع الحملات والصور داخل الاختبارات مؤقتة ومعزولة عن بيانات الخادم.

## حدود الموارد ومراجعة النشر

رفع الصور يتحقق من جلسة المدير وCSRF قبل قراءة الجسم، ويحد المعدل بعشر محاولات في الدقيقة. يفك Pillow المثبت في lock الصورة ويعيد ترميز بكسلاتها دون EXIF أو metadata، ويرفض الصور المتحركة والناقصة والأبعاد الكبيرة. تفحص أبعاد WebP قبل فتح مفككه الأصلي، ويقتصر فك الصور على مهمتين متزامنتين. حجم الصورة الخام والمخرجة ≤2MB. طلبات JSON للإعلانات ≤64KiB. لا تُقبل SVG أو أكواد HTML أو روابط JavaScript.

تُعاد الاستفادة من البوستر نفسه ببصمة محتواه بعد التنظيف. الحفظ حصري تحت قفل قاعدة البيانات، مع سقف 256MiB و2000 ملف لمجلد بوسترات الإدارة؛ الوصول للسقف يعيد خطأً واضحاً ولا يحذف صوراً مستخدمة. تنظيف الملفات القديمة غير المشار إليها إجراء إدارة يُراجع قبل تنفيذه. الصور المنظفة عامة وصالحة للتخزين المؤقت immutable؛ لا ترفع إليها صوراً خاصة.

اختيار الحملات يستخدم فهارس وترتيب SQL، ويعيد حتى 20 مرشحاً: ثلاثة مفضلين، وبوستر بديل، والإعلان المعروض لكل موضع. لا تنمو الاستجابة بعدد جميع الحملات، ولا توجد استعلامات Python منفصلة لكل حملة. تُنظف بيانات زيارات البنرات المنتهية وتفضيلات الإغلاق المنتهية كل ساعة عند تسجيل زيارة، وتبقى سجلات المشاهدات السابقة محفوظة. لا تكتب الزيارات عندما لا توجد حملة تستهدف السياق؛ الأحداث القديمة تبقى منفصلة عن زيارات المواضع الجديدة.

تقص الواجهة النص المخصص إلى سطور محدودة، وتسمح بكسر الكلمات الطويلة، دون قص محتوى Google. تستخدم الوحدة الأفقية `data-full-width-responsive=false`، والجوانب قياساً صريحاً 160×600px. لا تفعّل Auto ads أو تحسينات توسيع الوحدات من حساب Google دون إعادة فحص التصميم؛ إعدادات حساب Google قد تضيف مواضع خارج تحكم المنصة.

تشخيص العميل متاح في Console عبر `StudioAdvertising.status()` دون مفاتيح أو نصوص حملات. يعرض حالة التحميل وعدد الطلبات وآخر سبب فشل؛ لا يدعي معرفة أرباح أو موافقة Google. API إعدادات المدير يعرض نطاق تحقق الإعدادات صراحة. راجع [تقرير المراجعة وحدودها](ADVERTISING_REVIEW.md).

قائمة الإدارة مقسمة إلى صفحات من 25 حملة؛ البحث والتصفية يشملان المخزون كله على الخادم، ويعيدان الصفحة إلى الأولى. تقبل API حدّاً حتى 100 سجل للصفحة. لا يُنشئ المتصفح آلاف بطاقات الحملات دفعة واحدة.

تقبل جدولة الحملات تواريخ حتى بداية 2100؛ ترفض القيم غير المنتهية أو الضخمة التي تتجاوز نطاق المحرر، قبل حفظها في قاعدة البيانات.

تُرفض أجسام JSON غير الصالحة أو المفرطة التداخل في واجهات الإعلانات برسالة 400، قبل وصولها إلى التحقق من النماذج أو قاعدة البيانات.
